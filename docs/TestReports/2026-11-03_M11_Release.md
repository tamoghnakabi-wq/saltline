# Test report: release packaging, update check and download site, 2026-11-03

All results below come from runs on 2026-11-03 on one MacBook Air M4 (macOS 27.2). Nothing here is estimated.
Nothing was published: no GitHub repository or release was created and the website was not deployed.

**Not tested yet:**
- The Windows build on Windows. It was built and packaged on the Mac; no Windows machine was available.
- Downloading from GitHub Releases or the deployed site, because neither exists yet.
- The update check against the real site, for the same reason. It was tested against local files.

## 1. What was built

- **Release packaging** (`Tools/package_release.py`). Checks that both release builds match `BuildInfo.cs` and the
  current commit, zips them, verifies the zips, writes `SHA256SUMS.txt` and checks it with `shasum -a 256 -c`,
  and writes `release.json` (for the site) and `version.json` (for the game's update check).
- **Build stamps.** Each build now writes `SALTLINE.buildinfo.json` next to it: version, protocol, target, release
  or development, commit, uncommitted changes, update URL and Unity version. The packager refuses a build that
  does not match.
- **Update check** (`UpdateCheck.cs`). On launch the menu reads `version.json` from the site. If this build's
  protocol or version is below the published minimum, Host, Join and Browse are disabled, an update panel with a
  Download button replaces the cards, and the session calls refuse to run. A newer version that is still
  compatible gets a note in the menu footer. If the file cannot be read, the footer says so and nothing is blocked.
- **Download site** (`Web/`, Next.js exported as static files). Downloads with size and SHA-256, install steps
  including the Gatekeeper and SmartScreen warnings, the map, weapons, rules, a gallery from the game's own
  renders, release notes, known limitations and credits. It is built from the packager's `release.json` and
  serves `version.json`.
- **README**, release notes for 0.1.0 (`docs/releases/0.1.0.md`) and `docs/DISTRIBUTION.md` (versions, update
  check, packaging, signing, the publishing checklist).
- **Fix:** the effects showcase in `-maptour -fx` showed one test panel in magenta, because it looked up a
  material (`M_Container`) the map no longer uses. It now uses `M_Metal` and falls back to a name prefix.
- **Fix on the site:** at phone width (375 px) the page was 536 px wide, because the one-line `xattr` command
  stretched the Mac install card. The install cards can now shrink; the command scrolls inside its box.

## 6. Signing and Gatekeeper

The findings, with the commands and their output, are in `docs/DISTRIBUTION.md`. In short:

- **macOS:** the app is signed ad hoc. On this Mac (macOS 27.2) a copy unzipped from a release zip and given the
  quarantine flag of a download was rejected by `spctl --assess`, and `syspolicy_check distribution` failed with
  "Notary Ticket Missing". Players have to allow it once under System Settings > Privacy & Security > Open Anyway
  (Control-click > Open no longer works since macOS 15), or remove the quarantine flag in Terminal. The website
  and README say how. Notarization needs a Developer ID certificate, which only comes with the paid Apple
  Developer Program; it was not bought.
- **Windows:** the executable is not signed. Every signing route found is paid; SignPath Foundation's free
  signing is only for open-source projects without proprietary parts, which SALTLINE (Unity runtime, Mixamo
  animations) is not. SmartScreen's warning was not seen, because no Windows machine was available.

## 7. Not done: needs the owner

Nothing was published. These are decisions for the owner, in the order of the checklist in
`docs/DISTRIBUTION.md`:

1. Create the GitHub repository, public or private (downloads from a private repository need a GitHub login).
2. Choose a licence; the repository has none.
3. Create the Vercel project for `Web/` and decide the site's address. Then set `BuildInfo.UpdateManifestUrl`,
   rebuild, package with `--repo` and `--site`, create the release and deploy.
4. Whether to pay for an Apple Developer membership (notarization) or a Windows code-signing certificate.

## 8. Known limitations

- The Windows build has not been run. Its packaging was checked file by file, not by running it.
- The update check has only read local files. Its first real test is after the site is deployed.
- The update check is not a security measure. Offline, or with the address blocked, nothing is blocked, and a
  modified build can skip it. The protocol check when a player connects is what keeps incompatible builds apart.
- The Gatekeeper prompt was checked with `spctl` and `syspolicy_check`, not by opening the quarantined app.
- The site was viewed in one browser engine, the in-app browser.
